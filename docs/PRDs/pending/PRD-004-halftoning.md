## Goal

The `dtg-engine` crate's `halftone` module turns separation rows (PRD-003) into the
printer's **2-bit dots**:
- white at 1440 × 1440 dpi (1440 × 720 in the fast white mode);
- colour at 1440 × 720.

It works one 16-line band at a time, as a `BandSource` the print-file writer (PRD-005)
encodes directly. Ink use per tone must match Garment Creator's within a few per cent, with
no visible patterning.

## Why

- **Business value**: halftoning decides how a print looks, and how much ink it costs.
  Matching Epson's ink use keeps prints as durable and washable as Garment Creator's.
- **Integration**: it closes the gap between PRD-003 and the existing writer
  (`f2000::raster`, proven byte-exact on 88 files).
- **Problems solved**: Epson's halftone library and tables are proprietary and can't be
  used (no Wine, no Epson code). We need our own that is fast, open and good.

## What

### Method

- **Placement and resampling.**
  - Artwork is mapped onto the page: origin at the platen's top-left, page width = platen
    width, page length = design top + design height (as Garment Creator does).
  - It's resampled to device resolution with an area-averaging filter, separately per
    axis, because x is 1440 and y is 720 or 1440.
- **Multi-level blue-noise ordered dithering.**
  - Each pixel gets a dot size 0–3 by comparing its calibrated tone against three
    thresholds from a 256 × 256 blue-noise threshold array (void-and-cluster).
  - Each channel uses a different array offset, so cyan, magenta, yellow and black dots
    don't stack.
  - Chosen over error diffusion because:
    - every pixel is independent, so bands parallelise and stream with no state carried
      between them;
    - it's deterministic;
    - it has no "worm" artefacts or directional streaks;
    - it's cache-friendly, which keeps it quick on old CPUs.
  - Error diffusion stays possible later as an alternative mode behind the same trait.
- **Calibration to Epson.**
  - From the private reference set, measure for each ink channel and print mode the
    **dot-size mix per input tone**: the fraction of small, medium and large dots, and the
    total ink units. Use the grey ramp (03), the colour patches (02), the transparency ramp
    (05), and the full-coverage squares (01, 04).
  - Store it as small transfer tables, 256 entries per channel and mode, generated by a
    tool from the reference set. They're our measurements, not Epson data.
- **Threshold arrays** are produced by a deterministic generator in this repo (seeded
  void-and-cluster). The generated array is committed together with the generator and a
  test that regenerates it, so anyone can rebuild it from source.
- **Modes:**
  - Colour quality (8/10/16 passes) changes nothing here. Proven: identical dots; only
    the printer's weaving byte changes.
  - The white modes differ: 300210 is 720 dpi; 300230 lays about 30 % fewer dots. Each
    gets its own calibration.

### Engineering requirements

- **Band streaming:**
  - Implements `f2000::raster::BandSource` (PRD-001).
  - Pulls separation rows from PRD-003's pipeline just ahead of the band.
  - Working memory is about two bands plus the resampling window.
- **Parallelism:** the channels of a band, or groups of bands, across `std::thread::scope`.
  The output doesn't depend on thread count.
- **No new dependencies.**

### Success criteria

- [ ] **Ink per tone** within ±3 % of Garment Creator's on the grey ramp, colour patches
  and transparency ramp, per channel and per mode, measured with `f2000::render::ink_totals`
  over matching regions.
- [ ] **Full coverage** (01 on light, 04 white square): within ±1 % of Garment Creator's
  ink, and a matching dot-size mix (mostly large dots).
- [ ] **No patterning:**
  - Renders of flat patches show no visible texture at 100 % zoom.
  - A radially averaged power spectrum of a 50 % patch shows the blue-noise shape (low
    energy at low frequencies).
- [ ] Deterministic across OSes and thread counts (hash test).
- [ ] The matched 14 × 16 in job is halftoned and encoded in **< 10 s** with peak memory
  **< 192 MB**, colour engine included, on the 2014 iMac.
- [ ] The print file our pipeline makes for the matched job passes `f2000 verify`
  (self-consistent), and its render looks like Garment Creator's side by side.

### Known gotchas

```
# Dot size codes 0..3 sit 2 bits per pixel; the leftmost pixel is in the TOP two bits of
#   each byte (see Plane docs).
# Colour lines are 1440 wide × 720 tall: a colour pixel is twice as tall as it is wide.
#   Resample y separately; the blue-noise array is in device pixels, not square inches.
# "Use garment black" happens in PRD-003, not here. Black areas arrive as zero ink.
# Edge crop (16-px left alignment, even width when compressed) is the writer's job; just
#   output full-width rows.
# Calibration tables must be generated by `calibrate`, never hand-edited.
```

## Implementation blueprint

### Data models

```rust
pub struct HalftoneMode { pub channel: u8, pub vres: u32, pub table: &'static Transfer }
pub struct Transfer { pub thresholds: [[u8; 3]; 256] }   // tone → three cut levels for sizes 1..3
pub struct Halftoner<'a, S: SeparationSource> { /* placement, modes, band buffers, source */ }
impl<S: SeparationSource> f2000::raster::BandSource for Halftoner<'_, S> { /* band() fills 2-bit rows */ }
```

### Tasks (in order)

```yaml
Task 1: Measure: write `calibrate` to read the reference set and print the dot-size mix and ink units per tone per channel per mode; record findings
Task 2: Blue-noise generator + committed arrays + regeneration test
Task 3: Resampler (area-averaging, separable), unit tests on synthetic patterns
Task 4: Halftoner as a BandSource; synthetic tests (0 % → no dots, 100 % → table's full-tone mix)
Task 5: Generate calibration.rs from Task 1; ink-per-tone tests against the reference set
Task 6: End-to-end on the matched job: colour engine → halftone → f2000 writer; render side by side; benchmark time and memory
```

### Pseudocode (only for non-obvious logic)

```
for each band y0..y0+16 (device lines), for each channel:
  tone = transfer_input(separation sampled at (x, y))      // 0..255 after resample
  t = mask[(y + offset_ch.y) % 256][(x + offset_ch.x) % 256] // 0..255
  size = 3 if t < cut3[tone] else 2 if t < cut2[tone] else 1 if t < cut1[tone] else 0
  // cut1 ≥ cut2 ≥ cut3 come from calibration, so the dot-size mix per tone matches Epson's
```

## Anti-patterns to avoid

- Don't chase byte-identical dots with Epson. The goal is the same look and the same ink.
- Don't add randomness without a fixed seed. Output must be reproducible.
- Don't hold full-page planes. Bands only.
