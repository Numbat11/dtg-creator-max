## Goal

Pushing a version tag (`v0.1.0`) builds, checks and publishes installable DTG Creator Max
releases on GitHub:
- **for Ubuntu:** a `.deb` and a tarball, with a menu entry and icon;
- **for macOS:** an app bundle in a `.dmg` or `.zip`, Intel and Apple silicon;
- **for Windows:** a `.zip` (and an `.msi` if cheap).

Every release has checksums, an embedded dependency list and build provenance.

## Why

- **Business value**: owners shouldn't need Rust to try it. Ready-made builds are also
  one of the ways the project pays for itself (kickoff brief §2), with support and paid
  builds alongside free source.
- **Integration**: builds on PRD-001's CI, toolchain pin and release profile.
- **Problems solved**: today the only way to run it is building from source.

## What

### Behaviour

- **The release pipeline: `cargo-dist`** (v0.34, MIT/Apache).
  - It generates a GitHub Actions release workflow.
  - It builds per target, makes archives and installers, writes checksums, and publishes
    to GitHub Releases.
  - Use its **`cargo-auditable`** option, which embeds the dependency list (a software
    bill of materials) in each binary, and its **GitHub attestations** option for
    provenance. Check both against its docs when building; option names change between
    versions.
- **Ubuntu:**
  - A `.deb` built with `cargo-deb` (desktop entry, icon, AppStream metadata,
    `Depends: libc6` only). Install with `sudo apt install ./dtg-creator-max_*.deb`.
  - A plain tarball as well.
  - Flatpak/Flathub is a follow-up. It needs device access for USB printing, which makes
    the sandbox weaker than Flathub likes. Decide after PRD-007.
- **macOS:**
  - An `.app` bundle with an icon.
  - Unsigned at first, ad-hoc signed. The release notes explain right-click → Open.
  - Notarisation needs a paid Apple developer account: a business decision, not this PRD.
- **Windows:** a `.zip` with the `.exe`. Unsigned, so SmartScreen will warn; code signing
  comes later, for the same cost reason.
- **App icon:** our own simple vector design (a T-shirt silhouette with a print-head dot),
  produced as SVG plus PNG sizes plus `.icns`/`.ico` from one source file in `assets/`.
  No Epson imagery.
- **Versions:** SemVer. Update `CHANGELOG.md` (Keep a Changelog) in the release PR. `0.x`
  until printing works end to end.

### Engineering requirements

- **Reproducible:**
  - Builds use the pinned toolchain and `--locked`.
  - The workflow is committed and generated by `cargo dist init`; regenerate it rather
    than hand-editing.
- **Small binaries:**
  - The release profile from PRD-001 (thin LTO, one codegen unit, stripped).
  - Target: < 20 MB per platform download.
- **No Epson data in any artefact** (PRD-002's guard test also runs in the release
  workflow).
- **Old hardware:**
  - Linux builds target `x86_64-unknown-linux-gnu` with the default CPU baseline, so no
    AVX2 is required. moxcms detects SIMD at run time.
  - The macOS minimum version matches eframe's.

### Success criteria

- [ ] Tagging `v0.1.0-alpha.1` produces release assets for Linux x86_64, macOS (x86_64,
  aarch64) and Windows x86_64, with checksums and provenance.
- [ ] On the Ubuntu MacBook, `sudo apt install ./…deb` installs it. DTG Creator Max appears
  in the app menu with its icon, opens, and opens a `.prn`.
- [ ] On a Mac, the app bundle opens after right-click → Open and shows the icon.
- [ ] `cargo auditable info` (or `rust-audit-info`) lists the dependencies from a released
  binary.
- [ ] Each download is < 20 MB.

### Known gotchas

```
# cargo-dist generates the workflow. Edit its config and regenerate; don't hand-edit.
# Unsigned macOS/Windows builds trigger OS warnings. Say so plainly in the release notes
#   and README; don't hide it.
# The .deb must not need GTK (rfd uses the XDG portal) and must not install udev rules.
# Keep icons as one SVG source plus a script to make the sizes, so it stays maintainable.
```

## Validation loop

### Level 1 — syntax & style

```bash
cargo dist plan            # Expected: the targets and artefacts listed, no errors
desktop-file-validate assets/linux/dtg-creator-max.desktop
appstreamcli validate assets/linux/dtg-creator-max.metainfo.xml
```

### Level 2 — unit tests

```bash
cargo test --workspace --locked
```

### Level 3 — integration

```bash
cargo deb -p dtg-creator-max && sudo apt install ./target/debian/dtg-creator-max_*.deb   # on Ubuntu
git tag v0.1.0-alpha.1 && git push origin v0.1.0-alpha.1   # only with the owner's go-ahead
```

### Level 4 — manual verification

- [ ] Ubuntu: app menu entry, icon, launches, opens files by double-click (MIME types for
  `.prn`/`.gcr`).
- [ ] macOS: opens; icon right; the right-click → Open instructions are accurate.
- [ ] Release page: clear notes, checksums, and honest unsigned warnings.

## Anti-patterns to avoid

- Don't push release tags without the owner's go-ahead.
- Don't hand-edit generated workflows.
- Don't bundle anything Epson made, including icons or garment pictures.
